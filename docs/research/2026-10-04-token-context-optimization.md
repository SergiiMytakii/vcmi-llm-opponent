# Уменьшение контекста игрового контроллера без потери информации

Дата проверки: 2026-10-04. Анализ кода, сохранённых запросов и локальных экспериментов с представлением данных. Изменения контроллера и игровые прогоны в рамках исследования не выполнялись.

## Decision To Unblock

Как уменьшить примерно 76 тысяч входных токенов одного решения, сохранив доступные действия, факты, память и качество стратегии. Сохранение информации проверяется отдельно от качества решений модели: первое можно доказать обратным преобразованием, второе требует сравнительных испытаний.

Текущий контроллер: `controller/codex.py::choose`, Codex CLI 0.160.0, `gpt-6.1-sol`, medium, `--ephemeral`, без инструментов и истории. Полный запрос сериализуется через `json.dumps(request)`; отдельно передаются инструкции и JSON Schema ответа. Уже используются пакеты действий: предел выбранного запроса — 32. Память между решениями явно передаётся в запросе.

## Short Answer

Начать с UTF-8 и компактного JSON, затем вынести строго одинаковые подструктуры в общий словарь. На восстановленном запросе с зарегистрированными 76 325 входными токенами локальная оценка доступных текстовых компонентов снижается с 74 193 до 56 807 токенов только за счёт сериализации, до 42 247 после дедупликации, до 37 617 после дополнительной табличной записи. Это приблизительно 23%, 43% и 49% соответственно; результаты последовательные и не складываются.

Это локальные оценки размера, а не измеренные новые ответы сервера. Все варианты сохранили данные при обратном преобразовании, но качество решений модели ещё не проверено. Сокращать факты, число действий, неопределённость или стратегические правила для получения этих результатов не требуется.

Для измерения восстановлен контекст обучения из `.build/experience.sqlite3`, открытой через SQLite `mode=ro`: game `4b29bbbe-523d-49fb-b678-10a108534fc4`, request `0:6:0`, episode `3daf621e73d7125229966ddf`. Полный фактический stdin Codex тогда не архивировался; восстановление — сильное свидетельство, но не побайтовая запись отправленного текста.

Manifest первоначально показывает experience off, однако отдельный `experience-policy-change.json` фиксирует включение learn в 17:49:59 UTC, до выбранного решения в 17:52:46 UTC. Поэтому manifest сам по себе не описывает режим этого решения.

Инструкции совпадают по SHA-256 со снимком manifest. `experience.py` также совпадает. `codex.py` и `main.py` изменялись после подготовки старого прогона; анализ учитывает текущий код, а не заявляет полную идентичность исторического исполнения текущему checkout. Локальный счётчик: `tiktoken 0.14.0`, `o200k_base`. Автоматического соответствия для `gpt-6.1-sol` установленный tiktoken не предоставляет, поэтому это явно обозначенная оценка. Сумма исходного текста запроса, инструкций и восстановленной схемы — 74 193 против зарегистрированных сервером 76 325. Разница 2 132 не приписывается определённой причине: возможны форматирование, токенизация и особенности восстановления. Нельзя выдавать эту разницу за подтверждённый постоянный overhead.

## Repository Implications

Следующие выводы — предложения по текущему коду, не утверждение о проверенном качестве игры после изменения.

1. **Первый шаг: сериализация на границе Codex.** Использовать `json.dumps(..., ensure_ascii=False, separators=(',', ':'))` для stdin и схемы. JSON-значения не меняются; обратное чтение всех проверенных вариантов равно исходным данным. Содержимое русских описаний сохраняется. Изменение `indent` в логах или pretty JSON движка само по себе не сократит модельный контекст, поскольку контроллер повторно сериализует запрос.

2. **Второй шаг: точная дедупликация внутри одного запроса.** Общие армии, strength, повторные sightings и одинаковые части маршрутов можно хранить один раз и ссылаться на них. В выбранном запросе 58 `actions[*].army` совпадают с армиями текущих visible_objects, 58 `combat.enemy` совпадают с соответствующим `army.strength`, а `memory.own_heroes` совпадает с `observation.heroes`. В локальном эксперименте выбирались повторяющиеся JSON dict/list с частотой больше одного и размером не меньше 40 оценочных токенов; они переносились в `$definitions`, повтор заменялся `$ref`. Получилось 90 определений. Декодирование вложенных ссылок полностью восстановило исходный запрос. Это измерение потенциала, а не требование внедрять такой универсальный формат: понятный предметный словарь может быть удобнее модели.

3. **Третий шаг: таблицы там, где структура повторяется.** Последовательные группы из двух и более объектов с одинаковым набором и порядком ключей представлялись единственным заголовком columns и массивом rows. Для смешанных массивов порядок сегментов сохранялся. Обратное восстановление равно исходным структурам, включая null, false, нули, отсутствие ключа и порядок элементов. Словарь и таблицы тоже совместно прошли проверку восстановления. Предпочтительны явные понятные заголовки; слишком плотный формат может осложнить модели сопоставление данных даже без потери фактов.

4. **Отдельный резерв: обучение и история.** Они повторяют целые snapshots и actions. Сначала дедуплицировать идентичные части. Затем можно исследовать snapshot + точные изменения ВНУТРИ самодостаточного запроса, сохраняя временные границы и доказательства signals. Не заменять наблюдённые последствия свободным пересказом, не удалять отрицательные результаты и не отключать learning ради экономии.

5. **Инструкции и схема — следующий приоритет.** Инструкции занимают примерно 5,8k, поэтому одно их сокращение не решит основной объём. Сжатая редактура или условное включение разделов требуют отдельных оценок качества; общие правила тумана войны, бюджетов, угроз, планов и исполнения нужны и при отсутствии прямого attack. Уже короткие action IDs и их два enum не являются главным источником 76k; нельзя снимать проверки membership/batch ради небольшого выигрыша.

6. **Кеширование рассматривать отдельно.** В выбранном решении кеша нет. Stable-prefix может уменьшить повторные вычисления, но не число токенов контекста. Эфемерный локальный процесс сам по себе не доказывает причину нулевого кеша; настройки API нельзя автоматически переносить на subscription CLI. Переход на платный API для этих предложений не требуется.

### Что пока не считать сохранением качества

- Top-K действий, удаление далёких объектов и старых enemy sightings сокращают варианты стратегии и информацию об угрозах.
- Округление costs/strength/travel, удаление uncertainty, route encounters, possible stops или фактов доставки войск меняют содержимое решений.
- Удаление описаний зданий может скрыть эффекты, не выраженные полностью в численных полях, особенно при модах.
- Передача только изменений МЕЖДУ вызовами не подходит текущему one-shot режиму: модель не получает предыдущий запрос. Сессия с накапливающейся историей также не гарантирует меньший контекст.
- gzip или base64 не дают модели читаемого меньшего представления при отключённых инструментах.

### Как проверить отсутствие регрессии

Сначала доказать round-trip каждого нового представления на разнообразных сохранённых запросах и проверить однозначное соответствие IDs, полное множество действий, порядок batches, временные snapshots и отсутствие утечки скрытой информации. После этого сравнить исходный и новый формат с одинаковой моделью, reasoning effort, инструкциями, references и experience snapshot.

Нужны сценарии строительства, покупок и доставки войск, захвата ранних wood/ore mines, выбора безопасного маршрута, stale threats, потери героя, повторного планирования и обучения на последствиях. Оценивать законность, бюджет пакета, стратегическую обоснованность, фактическое исполнение, таймауты и input/output/reasoning/cache usage. Совпадение одного action_id не является достаточным критерием качества; допустимы разные хорошие решения.

Обычный `playtesting.controller.replay` сохраняет native request, но не восстанавливает исторический контекст обучения: exchange передаёт read_only baseline либо off. Для честного сравнения нужен одинаковый подготовленный experience для обеих веток; наличие сырого request само по себе недостаточно.

Затем сравнивать полноценные игры на нескольких seeds против Nullkiller2 при impossible и подтверждённых назначениях игроков. Отдельно проверять результат всей игры; `reply_valid` не доказывает хорошую стратегию или победу. Размер сокращённого контекста можно подтвердить сразу по CLI usage, сохранение качества — только по результатам этих сравнений.

## Conflicts And Unknowns

- Нет точной записи дополненного stdin выбранного исторического запроса; experience восстановлен из сохраняемой базы и метаданных.
- Нет публичного соответствия установленного tiktoken конкретной модели; проценты относятся к явно указанному локальному счётчику.
- Новые representations не исполнялись моделью. Экономия числа токенов измерена локально, игровая эквивалентность не доказана.
- Нет доказательства доступности определённых API cache settings и их влияния на квоту подписки в CLI 0.160.0.
- Текущие native engine limitations и правила управления живыми сессиями не менялись; установленные игры, сохранения, профили и процессы не затрагивались.
