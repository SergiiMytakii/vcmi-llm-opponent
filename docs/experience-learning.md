# Обучение ExternalAI на игровом опыте

Игровой контроллер автоматически разбирает наблюдаемые последствия решений,
сохраняет условные уроки и передаёт подходящие уроки в следующие вызовы Codex,
включая новые партии. Это изменение поведения через память, без изменения
параметров модели. История чатов и личная память Codex не используются.

## Цикл

1. Контроллер сохраняет выбранное действие, наблюдаемые исходные условия и
   краткое ожидание модели. Резервное завершение хода отмечается как сбой
   инфраструктуры, а не намеренная стратегия модели.
2. Следующий запрос сопоставляется с прежними наблюдениями. Сигналами служат
   результаты команд, изменения собственной армии, владения героями/городами,
   ресурсов и проверка плана. Отсутствующее поле остаётся неизвестным; только
   полный собственный список подтверждает потерю владения.
3. До двух ещё не разобранных эпизодов вместе с последними восемью решениями
   поступают в тот же вызов модели, который выбирает следующее действие.
   Контекст опыта ограничен 32 КиБ; старые элементы траектории сокращаются
   при необходимости. Модель обязана оценить каждый предложенный эпизод,
   включая явную неопределённость, и сослаться на реальные идентификаторы сигналов.
4. `support` создаёт или подтверждает урок; `contradict` учитывает возражение;
   `uncertain` сохраняет разбор без усиления урока. `revise` выводит прежнее
   правило из использования и сохраняет уточнённое как новую гипотезу.
   Существующий подходящий урок переиспользуется вместо сохранения перефразировки.
5. До шести подходящих правил поступают перед следующим решением. Уроки с
   возражениями помечаются `challenged`; при достаточных противоречиях или
   явном уточнении — `retired`. Новые подтверждения могут вернуть правило
   в использование. Повторная обработка одного эпизода не меняет счётчики.

Первый вывод всегда является гипотезой. `supported` требует подтверждений в
трёх отдельных партиях игрока без возражений; это учёт повторяемости,
не доказательство причинности. Плохой исход сам по себе не доказывает ошибку.
Переносимые правила не должны содержать номера объектов, координаты, имена
карты/игроков или сведения о расположении противника. Фактические эпизоды
доступны только владельцу соответствующей партии; между партиями передаются
обобщённые правила. Сохранённые тексты не являются командами и не отменяют
инструкции контроллера или текущие наблюдения.

## Завершение игры и сохранения

Адаптер сохраняет случайный `experience_id` в namespace ExternalAI обычного
сохранения. Он независим от содержания карты, отдельный для каждого игрока,
стабилен между ходами и после загрузки того же сохранения. Контроллер получает
его в `memory.experience_id`. При откате сохранения сырые будущие наблюдения и
неразобранные эпизоды перестают использоваться; обобщённый уже полученный опыт
сохраняется.

При `gameOver` адаптер передаёт только подтверждённую собственную победу/поражение
и публичный календарь: `observation.terminal_result: win|loss`. Доступно только
`end_turn`; ответ не исполняет игровую команду и не меняет сохранённый план.
Финальный разбор ограничен обычным таймаутом транспорта, до 40 секунд, и может
задержать переход к экрану завершения. Принудительное закрытие/таймаут могут
прервать разбор; это отражается в диагностике. Новый движок нужно пересобрать:
прежние распространявшиеся сборки этого события и идентификатора не передают.

## Хранилище и тестер

По умолчанию контроллер хранит опыт в `.build/experience.sqlite3` рядом с
репозиторием. Необязательный `VCMI_EXPERIENCE_DB` задаёт другой SQLite-файл;
`VCMI_EXPERIENCE_MODE` имеет значения `learn` (по умолчанию), `read_only`, `off`.
При ошибке хранилища игровой контроллер продолжает работу без опыта и записывает
`experience_error`. Ошибочные ответы модели сохраняют существующее безопасное
резервное завершение хода. Изменения уроков и их доказательств транзакционны.

Тестер выбирает владельца автоматически по `purpose`:

- `training`: общая библиотека между партиями; `experience_database` в JSON
  позволяет указать её путь. Начальное состояние фиксируется снимком.
- `integration`: собственная библиотека внутри каталога запуска.
- `evaluation`: неизменяемый снимок исходной библиотеки, без обучения. Если
  библиотека ещё не создана, опыт отключён. Хеш снимка проверяется перед вызовом.
- Offline recording/replay: только начальный снимок, без изменения библиотеки.

`learning` существует только в ответе Codex для контроллера. После проверки и
записи контроллер удаляет его из ответа движку, сохраняя существующий протокол
`protocol/request_id/action_id/strategy`. Диагностика `experience` сообщает
число переданных правил, разобранных эпизодов и обновлённых уроков; тестер
включает её в `report.json`. SQLite сохраняет сигналы, траектории, разборы,
счётчики и связи уточнённых правил для проверки выводов.

## Проверки

```sh
python3 -m unittest discover -s tests -p test_experience.py -v
python3 -m unittest discover -s tests -p test_playtesting.py -v
```

Проверки используют реальные процессы контроллера/CLI и SQLite, с подставным
Codex на границе модели. `test_native_experience.py` — opt-in проверка реального
движка через `VCMI_NATIVE_EXPERIENCE_CONFIG`; она проверяет финальное событие
и сохранение урока, с подставной моделью. Native save/load и парные проверки
тумана войны проверяют идентификатор партии и сохранение изоляции наблюдений.
Это доказательство механизма, а не роста игрового мастерства. Рост доли побед
требует отдельного сравнения сопоставимых игр с опытом и без него.
